# Auto-VHS-Deinterlacer v1.0.4 — SHA256 Download Verification, Injection Fixes & `ram_cache_mb` Validation

This release hardens the installer against supply-chain and injection risks, tightens
config validation, and ships a full agent skills library alongside the new automatic
GitHub release workflow.

______________________________________________________________________

## 🔒 Security & Hardening

- **SHA256 integrity verification for all installer downloads**: `install.ps1` now
  fetches the upstream checksum file before accepting the FFmpeg static build, and
  verifies `havsfunc.py` against a pinned hash. Any mismatch deletes the download and
  aborts with a clear error — no silent corruption possible.
- **Batch argument injection fix**: the `start.bat` launcher (and the equivalent
  block generated by `install.ps1`) previously forwarded drag-and-drop files via bare
  `%*`, allowing crafted filenames to inject arbitrary batch commands. Fixed by
  replacing `%*` with a quoting loop using `"%~1"` per argument. `setlocal` added to
  isolate the batch environment.
- **`ram_cache_mb` config validation**: `config.py` now validates
  `manual_settings.ram_cache_mb` with the same strict pattern as `cpu_threads`:
  rejects non-integers, rejects values below 128 MB, and exits with a descriptive
  error. `vspipe.py` explicitly casts both `cpu_threads` and `ram_cache_mb` to `int`
  before writing them into the generated VPY script.
- **Install error clarity**: the `catch` block now includes `$_` so the actual
  exception message appears in the `[ERROR]` output line.

## 🤖 Agent Tooling

- Full skills library added under `.agents/skills/`: `code-linter`, `pipeline-runner`,
  `test-runner`, `installer-tester`, `release`, `resolve-pr-comments`,
  `review-with-coderabbit`, and `vapoursynth-pipeline-verifier`.
- `AGENTS.md` expanded with project overview, working rules, full validation command
  reference, and skills index table.

## 🚀 Automatic GitHub Releases

- New `.github/workflows/release.yml`: pushing a `v*` tag now automatically creates
  a GitHub Release. The workflow verifies the tag matches `pyproject.toml`, uses
  `docs/releases/v{VERSION}_github_description.md` as the release body (with
  auto-generated notes as fallback).

## 🔧 CI & Dependency Updates

- Markdown lint step (`ci.yml` + `run_pipeline_localy.ps1`) now passes `-d MD013` to
  `pymarkdown` to suppress line-length warnings.
- `pytest-cov ^7.1.0`, `pylint ^4.0.7`, `flake8 ^7.3.0`, `ruff ^0.16.4` — all bumped
  to current latest.

## 🧪 Validation

- New tests cover `ram_cache_mb` validation (valid string, multi-line injection,
  below-minimum), batch argument quoting (`%*` absent, `"%~1"` present), and SHA256
  verification landmark assertions in `install.ps1`.
- Full test suite passes; coverage gate ≥ 90% maintained across all files.
