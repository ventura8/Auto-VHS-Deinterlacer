# v1.1.4

Supply-chain hardening for the Linux installer, and FFmpeg 9.0.2 everywhere.
On Linux, `install.sh` used to fetch FFmpeg from BtbN's moving `latest` release
and verify it against a checksum file from that same release — a check that
proved only that the two files agreed with each other. All three platforms now
pin the exact FFmpeg release and its SHA-256 in the installer, refuse anything
that does not match, and replace an older bundle instead of silently keeping
it.

______________________________________________________________________

## 🔍 What's in this release

- **Linux FFmpeg is pinned** — `install.sh` downloads from the fixed BtbN tag
  `autobuild-2026-09-19-13-11` (the clean `n9.0.2` build) and checks the
  archive against a SHA-256 pinned in the script for both `linux64` and
  `linuxarm64`, the same way Windows and macOS already did. The co-hosted
  `checksums.sha256` is no longer downloaded. A mismatch deletes the archive,
  retries up to three times, then installs nothing.
- **FFmpeg 9.0.1 → 9.0.2 on all platforms** — evermeet.cx (macOS), gyan.dev
  (Windows) and BtbN (Linux) pins and hashes refreshed. Every hash was computed
  from an independently downloaded archive and cross-checked against the
  upstream-published value where one exists.
- **Upgrades actually upgrade** — the installers used to skip the download if
  any 9.0.x (Linux/macOS) or any `ffmpeg.exe` at all (Windows) was already in
  `.venv`. Both now require `ffmpeg` *and* `ffprobe` to report the exact pinned
  version, so a machine on 9.0.1 gets 9.0.2 on the next install run.
- **No stale bundle after a failed upgrade** — `install.ps1` now removes the
  old `ffmpeg.exe` / `ffprobe.exe` when the download or verification fails, so
  the app falls back to the system FFmpeg rather than the previous bundle. On
  Linux and macOS, a `cp`/`chmod` failure (disk full, permissions) no longer
  aborts the installer under `set -e`; it warns and lets the cleanup path run.
- **Linux installer path is tested** — the Linux block is now a self-contained
  `install_linux_ffmpeg` function, and the unit tests drive it with a stubbed
  `curl`: both architecture pins install a genuine archive from the fixed tag,
  a tampered archive is rejected and deleted on all three attempts, and
  download failure and unsupported architectures are covered. Each test was
  confirmed to fail when the guard it protects is removed.

## 🧪 Validation

- The full local pipeline passes end to end — Taplo, Bandit, pip-audit, Black,
  isort, Ruff, Flake8, Pylint (10.00/10), Radon complexity and maintainability
  (all grade A), Markdown lint, the test suite and both coverage gates.
  373 tests pass with no skips and no failures; the new Linux installer tests
  run on any host with a POSIX bash, including Git Bash on Windows. The
  2026-09-21 run reports 95.51% line coverage and
  87.18% branch coverage; the gate and the badge show 93.68%, the combined
  line-plus-branch figure for the same run.
- The rewritten installer paths were run against the live upstream releases:
  `install_linux_ffmpeg` installs `n9.0.2-20260919` from BtbN and rejects a
  tampered download three times; `install_darwin_ffmpeg` passes the new
  evermeet.cx 9.0.2 pins; a fake 9.0.1 pair in `.venv/bin` is replaced and a
  second run reports it already present. `install.ps1` parses under `pwsh` and
  its version matcher was checked against the evermeet, BtbN and gyan.dev
  version-string formats; the Windows installer end-to-end is covered by the
  Windows CI job rather than a local run.
