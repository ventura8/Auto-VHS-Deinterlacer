# v1.1.10

Fixes a high-severity code-execution path where a Python module planted in a
video's `.autovhs-tmp` workspace could be imported while vspipe evaluated the
generated script, and refreshes the dependency stack (PyTorch cu134, dev
tools, Poetry, GitHub Actions).

______________________________________________________________________

## 🔍 What's in this release

- **Workspace import isolation (security)**: the generated `restore.vpy` puts
  the trusted roots (install folder, venv site-packages, portable `vs/`) first
  and removes the workspace, the working folder and relative entries from
  `sys.path`, so modules beside the video can no longer shadow `havsfunc` or
  any other import.
- **Workspace sweep**: `prepare_workspace()` deletes anything the pipeline did
  not create (planted `*.py`, `__pycache__`, symlinks, Windows junctions)
  before each run, and stops the job if something cannot be removed.
- **Native fallback**: no longer adds the script folder to `sys.path`.
- **PyTorch cu134**: torch 2.15.0, torchvision 0.29.2, torchaudio 2.11.1 with
  matching CUDA 13.4 component pins.
- **Tooling refresh**: Poetry 2.5.1, black, ruff, pylint, flake8, pytest and
  GitHub Actions pins updated; pip-audit is clean.

## 🧪 Validation

- Full local CI-parity pipeline passes: linters, Pylint 10.00/10, Radon grade
  A, pip-audit clean, all tests passing, and >=90% line coverage per-file and
  repository-wide.
