# v1.1.5

## Summary

v1.1.5 adds SonarQube Cloud analysis to CI and to local runs, fixes everything
it reported, and then verifies the changed code on real hardware: an RTX 3080
Laptop GPU on Linux and an RTX 5090 on Windows 11. That hardware pass found
defects the existing tests could not see, the most serious being that AV1
masters encoded with NVENC carried an AV1 level the specification does not
define, so libaom refused to decode them.

## Highlights

### AV1 NVENC masters decode everywhere

- `av1_nvenc` wrote `seq_level_idx` 23 (AV1 level 7.3) into the sequence header,
  even for a 720x480 source. The AV1 specification defines levels only up to
  6.3, so libaom rejected the file (`Value 23 of seq_level_idx[0] is not yet defined`) while dav1d played it. For an archival tool, a master that a common
  decoder refuses is a real defect.
- `AV1_NVENC_ARGS` now pins `-level 5.1`, a mainstream tier that covers up to
  4K60. Verified on the RTX 5090: ffprobe reports level 13, libaom decodes all
  60 frames with exit 0, and the stream's encoder tag confirms `av1_nvenc`
  produced it.
- The E2E suite missed this because it only read container and stream headers.
  Every E2E output is now fully decoded, and AV1 outputs must report a defined
  level. The level is checked separately because FFmpeg decodes AV1 with dav1d,
  which accepts the out-of-spec level, so a decode alone would still pass.
- The AV1 E2E test now also asserts that the encoder recorded in the stream is
  `av1_nvenc` exactly when hardware detection reported AV1 NVENC, so a silent
  fallback to the CPU encoder on NVENC hardware fails the test.

### The installers check NVENC

- After installing FFmpeg, `install.sh` and `install.ps1` encode one real
  `av1_nvenc` frame and report whether AV1 output will run on the GPU, and if
  not, why: a GPU with NVENC but no AV1 encoder (RTX 30 series and older), a
  driver older than the bundled FFmpeg's NVENC SDK (quoting the minimum driver
  FFmpeg names, for example 610.00), or another probe failure.
- On Linux, `install.sh` installs the NVENC userspace library
  (`libnvidia-encode.so.1`) when an NVIDIA driver is present without it:
  `libnvidia-encode-<branch>` on Debian and Ubuntu, versioned to match the
  running driver, `xorg-x11-drv-nvidia-cuda-libs` on Fedora and `nvidia-utils`
  on Arch. Ubuntu's headless and server driver flavours omit this library,
  which otherwise fails silently. The kernel driver itself is never installed
  or upgraded. `AVD_SKIP_NVENC=1` skips the step.
- The Windows probe relaxes the installer's `Stop` error preference locally.
  Without that, the expected probe failure threw `NativeCommandExitException`
  and would have aborted the install on every machine without AV1 NVENC. The
  first version of that guard used `SilentlyContinue`, which on Windows
  PowerShell 5.1 discarded the probe's stderr and left every failure reported
  as a blank warning; it now uses `Continue` and unwraps each error record.

### SonarQube Cloud

- `sonar-project.properties`, a CI scan step pinned to
  `sonarqube-scan-action` v8.2.2 with the quality gate enforced, and
  `tools/run_sonar_scan.sh` for local runs from the scanner's Docker image. The
  step is skipped with a warning when `SONAR_TOKEN` is absent, so a missing
  token does not block fork pull requests.
- `.github/scripts/**` and `tools/**` are excluded from the coverage metric:
  they are analysed for issues but sit outside the pytest coverage scope, and
  counting them reported 82.4% against the real figure of about 93.7%.
- All 32 reported issues are fixed, none suppressed: 2 bugs, 28 code smells
  from the first analysis, and 2 shell findings that only SonarCloud's shell
  analyser raised. The pull request analysis reports 0 bugs, 0 code smells,
  0 vulnerabilities and 0 security hotspots. `main` had never been analysed
  before this release; its first analysis runs when this release is merged.
- `AGENTS.md` and `.agent/validation.md` extend the zero-suppression rule to
  `# NOSONAR` and to resolving SonarQube issues as "Won't fix" or "False
  positive" instead of fixing them.

### Code fixes

- **Audio tempo correction** — the exact float comparison `atempo != 1.0` is
  replaced by a tolerance check. FFmpeg's `atempo=1.000000` is not a no-op: it
  resamples and trims a fixed ~1 ms from the tail (measured identical at 5 s
  and 30 s), so dropping a correction that rounds to unity keeps the audio
  bit-exact.
- **FFmpeg progress parsing** — the speed regex no longer backtracks
  super-linearly, and a malformed token such as `speed=1.x` is rejected.
- **VPY generation** — the QTGMC fallback body is a single template instead of
  a 40-line chain of `lines.append` calls. The generated script is
  byte-identical, checked by comparison.
- Smaller clean-ups in `vspipe.py`, `patch_havsfunc.py` and
  `coverage_paths.py` from the Sonar findings.

### Tests that now reach what they name

- `test_scenario_av_drift_correction` never exercised drift correction: its
  fixture drifts by about 5%, which the percentage guard always rejects. A new
  fixture drifts by 0.4% and `test_scenario_av_drift_applies_real_atempo`
  drives a real encode through the correction.
- The QTGMC fallback chain is generated into the VPY script, so it had never
  run anywhere. `test_qtgmc_fallback.py` loads the real template and covers
  every branch: an unsupported `device` keyword, missing OpenCL plugins,
  missing `fmtc`, the Bob fallback, the retry ceiling, and Bob itself being
  unavailable.

### Dependencies

- Updated to the latest releases allowed by the constraints: filelock 4.0.1,
  urllib3 2.8.0, coverage 7.16.1, ruff 0.16.8, plus idna, platformdirs,
  pyparsing, wcwidth and pip-api. astroid and mando stay at the versions that
  pylint's and radon's own ranges allow.

## Validation

- The full local pipeline (`./run_pipeline_localy.sh`) passes end to end.
  Taplo, Bandit, pip-audit, Black, isort, Ruff, Flake8, Pylint (10.00/10),
  Radon complexity and maintainability (all grade A), Markdown lint, the test
  suite and both coverage gates all pass. 407 tests pass with no skips and no
  failures (373 in v1.1.4). The run reports 95.48% line coverage and 87.18%
  branch coverage; the gate and the badge show 93.64%, the combined
  line-plus-branch figure. Every product file is above the 90% per-file line
  threshold. PowerShell lint, shellcheck and `bash -n` also pass on both
  installers.
- Every check was confirmed by exit code rather than by printed output. Pylint
  prints a 10.00/10 rating while exiting non-zero for convention messages,
  which hid a line-limit breach during this release until CI caught it.
- Hardware, with real detection (`AUTO_VHS_SKIP_HW_DETECT` unset, unlike CI):
  - **RTX 3080 Laptop, Ubuntu 26.04, driver 595.91.07** — 41 frames of real
    QTGMC output through the generated script with OpenCL on the GPU; a real
    encode through the drift correction (`atempo=1.004000`); live FFmpeg
    progress parsed by the new regex; the Linux installer step in both of its
    failure modes.
  - **RTX 5090, Windows 11, driver 616.92** — the AV1 NVENC encode with the
    level pin (level 13, libaom decodes it, encoder tag `av1_nvenc`); the
    `install.ps1` NVENC section under Windows PowerShell 5.1 and PowerShell 7.6,
    reporting `[OK]` on the real card and the correct message on a forced
    failure, with nothing thrown and the installer's error preference
    unchanged afterwards.
- New tests were checked against deliberate regressions: all three
  `install.sh` mutations tried are caught, and removing the PowerShell guard
  fails three of the four probe tests.

## Known issues

- Unchanged from v1.1.4: `poetry lock` cannot re-resolve from scratch, because
  `nvidia-cuda-runtime 13.2.86` conflicts with the `==13.2.75.*` that
  `torch 2.14.0+cu132` requires. The committed lock is consistent
  (`poetry check --lock` passes), so installs and CI are unaffected.
- Found during this release, not caused by it: the E2E fixture
  `temporary_config_override` writes over the tracked `config.yaml` in the
  repository root, so an interrupted E2E run leaves the file replaced and a
  later `git add -A` commits it. This release restored the file after exactly
  that happened.
- The bundled FFmpeg 9.0.x needs NVIDIA driver 610.00 or newer for any NVENC
  encoder. Older drivers fall back to CPU AV1, and the installers now say so.
- One Windows CI run failed two zip-slip tests in
  `test_install_darwin_ffmpeg_rejects_bad_archive_members` and passed on a
  rerun of the same commit. Those tests and the installer code they cover are
  unchanged in this release.
