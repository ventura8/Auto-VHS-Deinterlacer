# v1.1.3

Crash-safe, resumable encoding and strict temp-file hygiene. Every temporary and
cache artifact now lives in a single per-video workspace folder next to the
source, video is encoded in resumable segments so an interrupted run continues
from the last finished segment instead of starting over, and the workspace is
deleted once the final output is in place — so a successful run leaves nothing
behind but the output file.

______________________________________________________________________

## 🔍 What's in this release

- **One temp folder per video** — the generated script, source indexes,
  segments, concat list, resume state and the in-progress muxed output all live
  in `<name>.autovhs-tmp/` beside the source. Nothing is written to the system
  temp folder or next to the source any more.
- **Resume after a power cut** — video is encoded in `resume_segment_minutes`
  chunks (default 5, `0` disables). Each segment is written as `*.part.*` and
  renamed only on clean exit, so a segment is either absent or complete.
  Re-running the same file reuses finished segments and redoes only the
  interrupted one.
- **Resume safety fingerprint** — `state.json` records the source identity and
  every setting that shapes the video (encoder, mode, field order, TV standard,
  QTGMC settings, segment length, the resolved FFmpeg encoder arguments and the
  QTGMC OpenCL device settings). If any of them changed, old segments are
  discarded instead of being mixed with new ones, so a GPU-encoded segment is
  never concatenated next to a CPU-encoded one.
- **Guaranteed cleanup** — the workspace is removed as soon as the output is
  renamed into place, or when a valid output already exists. It is kept only on
  failure, and the log then tells you to re-run the same file to resume.
- **Leaks closed** — the `_temp_script.vpy` and `_part` files beside the source,
  and the FFMS2 index cache in the system temp folder, were never cleaned up on
  an interrupted run. Leftovers from earlier versions are now swept
  automatically on start-up.
- **Safer legacy cleanup** — the old cleanup deleted every `*.vpy` in the source
  folder and any file whose name merely contained `temp`, which could remove a
  user's own files. It now matches only artifacts derived from the input name.
- **Separate mux stage** — segments are joined with stream copy (no re-encode)
  and the source audio is muxed in at the end, with drift correction applied
  there instead of during video encoding. Video-only sources finalize normally
  because the audio mapping is optional.
- **Whole-file progress** — the progress bar, timestamp and ETA stay continuous
  across segments instead of restarting for each one.
- **Longer index probe timeout** — the `vspipe --info` probe builds the source
  index on first run, which takes minutes on a long capture and previously
  aborted the job after 30 seconds.
- **Native fallback frame ranges** — the Python `vspipe` fallback now accepts
  `--start` / `--end` with the same inclusive-end semantics as `vspipe`.

## 🧪 Validation

- The full local pipeline passes end to end — Taplo, Bandit, pip-audit, Black,
  isort, Ruff, Flake8, Pylint (10.00/10), Radon complexity and maintainability
  (all grade A), PowerShell lint, Markdown lint, the test suite and both
  coverage gates. 330 tests pass with 1 skip (the POSIX-only `install.sh`
  installer scenario, covered by the Linux and macOS CI jobs) and no failures.
  The 2026-09-17 run reports 95.54% line coverage and 86.96% branch coverage;
  the gate and the badge show 93.68%, the combined line-plus-branch figure for
  the same run. The new workspace module is at 100%.
- Hardware-validated on an RTX 5090 (Windows) and an RTX 3080 Laptop (Ubuntu)
  with real hardware detection: power-cut resume on a real PAL capture, AV1 on
  both the NVENC and CPU paths, a source replaced under the same name, and a
  folder scan with a custom output suffix all passed on both machines, each
  leaving only the source and the final output behind.
- Fixed along the way: AV1 encoding could never use the CPU path on a default
  Windows install, because it hard-coded `libsvtav1` while the bundled gyan.dev
  *essentials* FFmpeg ships libaom instead. The encoder is now chosen from what
  the active FFmpeg actually provides. The same failure reproduces at `v1.1.2`,
  so this predates the release.
