# Release v1.1.10 - Workspace Import Isolation & Dependency Refresh

## Security

- **Fixed (HIGH): per-video workspace import hijack during vspipe evaluation.**
  vspipe evaluates `restore.vpy` with the script folder (the
  `<video>.autovhs-tmp/` workspace beside the source) as its working
  directory. The generated header inserted the app working folder first and
  only appended the venv site-packages, so a `havsfunc.py` shipped inside a
  pre-populated workspace (archive, USB stick, shared folder) was imported
  instead of the venv copy and ran as the user.
  - `modules/runtime/vspipe.py`: the generated header now rebuilds `sys.path`
    with the trusted roots first (project root, venv site-packages, portable
    `vs/`, optional `mvsfunc/`) and drops `''`, relative entries, the script
    folder and the evaluation working folder. The project root now comes from
    `get_project_root()` instead of the process working directory.
  - `modules/runtime/vspipe_native.py`: the native fallback no longer appends
    the script folder to `sys.path`.
  - `modules/runtime/workspace.py`: `prepare_workspace()` first runs
    `remove_foreign_entries()`, which deletes anything in the workspace root
    the pipeline did not create (planted modules, `__pycache__`, symlinks) and
    replaces a symlinked workspace root with a real folder.
  - `tests/unit/test_vpy_import_isolation.py`: subprocess-based regression
    tests prove a planted `havsfunc.py` is imported without the fix and never
    with it, plus coverage of the workspace sweep and the native runner.
