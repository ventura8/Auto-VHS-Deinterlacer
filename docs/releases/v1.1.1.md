# v1.1.1

## Summary

v1.1.1 refreshes dependencies and improves the restoration pipeline. Every
production and CI dependency was audited against its upstream registry and moved
to the latest final version, the VapourSynth runtime was advanced to R79, and the
GitHub Actions toolchain was re-pinned to current commit SHAs. The update also
adds GPU-aware deinterlacing and QTGMC configuration, optional-plugin handling,
native-frame-streaming fallback, and runtime version reporting.

The CUDA component pins were investigated for an upgrade to CUDA 13.3.1 and
deliberately left on 13.2 — see [CUDA 13.3.1](#cuda-1331) below.

## Highlights

- **Pipeline reliability and GPU support**:
  - GPU-aware deinterlacing and QTGMC configuration now select compatible
    hardware acceleration where available.
  - Optional VapourSynth plugins are handled safely, native frame streaming is
    available as a fallback, and the CLI reports the installed application
    version at runtime.
- **Production dependencies**:
  - `audio-separator` `^0.44.3` → `^0.47.0`.
  - `onnxruntime-gpu` `^1.27.0` → `^1.29.0`.
  - `librosa` `^0.11.0` → `^1.0.0` (major). `audio-separator` requires only
    `librosa>=0.10`, so the major bump is satisfied without conflict.
  - `vapoursynth` `==77` → `==79`, propagated to `install.sh`, `install.ps1`,
    `docker/Dockerfile.ubuntu`, and the corresponding assertion in
    `tests/e2e/test_dockurr_containers.py`. R79 publishes the same `abi3` wheel
    matrix as R77 (Windows, macOS x86_64/arm64, manylinux, musllinux).
  - `torch` `2.13.0+cu132`, `torchvision` `0.28.0+cu132` and `torchaudio` `2.11.0`
    were already at the latest final versions and are unchanged. The
    `torch 2.14.0+cu132` artifacts present on the PyTorch wheel index are staging
    builds — they have no PyPI record and no upstream release tag — and were
    therefore not adopted.
- **Developer tooling**:
  - `isort` `^8.0.1` → `^9.0.1` (major), `pylint` `^4.0.7` → `^4.0.8`,
    `ruff` `^0.16.4` → `^0.16.5`, `mdformat-frontmatter` `^2.0.8` → `^2.1.2`.
  - `pytest`, `pytest-cov`, `flake8`, `radon`, `black`, `taplo`, `bandit`,
    `pip-audit`, `mdformat`, `pymarkdownlnt`, `genbadge` and `defusedxml` were
    already current and are unchanged.
- **CI/CD**:
  - Poetry `2.4.1` → `2.4.2` across `ci.yml`, `install.sh`, `install.ps1`,
    `run_pipeline_localy.sh` and `run_pipeline_localy.ps1`.
  - `actions/setup-python` `v6.3.0` → `v7.0.0`. The only removal in v7 is the
    `pip-install` input, which this project does not use.
  - `actions/upload-artifact` `v6.0.0` → `v7.0.1`. The v7 `archive` input is
    opt-in and defaults to the previous behaviour.
  - `softprops/action-gh-release` `v3.0.2` → `v3.0.3`.
  - `actions/checkout` `v7.0.1` and `actions/download-artifact` `v8.0.1` were
    already current. All actions remain pinned to full commit SHAs.
  - FFmpeg remains at `9.0.1`, still the latest upstream release.

## CUDA 13.3.1

CUDA 13.3.1 was released upstream on 2026-06-29 (`cudart 13.3.29`,
`nvrtc 13.3.33`, `cublas 13.6.0.2`) but **cannot be adopted by this project yet**.

The prebuilt `torch 2.13.0+cu132` wheel is built and tested against CUDA 13.2.
Raising the separately pinned CUDA component versions was not adopted because no
`cu133` Torch build was found on the checked PyTorch stable, test, or nightly
wheel indexes.

The four NVIDIA pins therefore remain aligned with the selected CUDA 13.2 Torch
wheel, and `pyproject.toml` now carries an inline comment recording this
constraint so the finding is not re-derived on the next dependency sweep.
