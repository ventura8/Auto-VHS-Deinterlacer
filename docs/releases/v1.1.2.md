# v1.1.2

## Summary

v1.1.2 closes a supply-chain integrity gap in the macOS installer and refreshes
every production and CI dependency to its latest final version.

`install.sh` downloaded the bundled FFmpeg 9.0.1 and FFprobe 9.0.1 builds from
evermeet.cx over HTTPS but, unlike the Windows and Linux installers, never
verified the archives before extracting them and placing the binaries first on
`PATH`. The Darwin branch now pins the SHA-256 of both archives, refuses to
install on mismatch, and extracts with a zip-slip guard.

On the dependency side, Torch `2.14.0` is now a genuine PyPI final (it was only a
staging artifact at v1.1.1 time) and is adopted together with TorchVision
`0.29.0`; the CUDA 13.2 component pins move to CUDA 13.2 Update 1; and
`onnxruntime-gpu`, `ruff`, `pymarkdownlnt` and Poetry are bumped. The CUDA
toolkit series stays on 13.2 — see [CUDA 13.3 / 13.4](#cuda-133--134) below.

## Highlights

- **macOS FFmpeg supply-chain hardening** (`install.sh`):
  - The SHA-256 of `ffmpeg-9.0.1.zip` and `ffprobe-9.0.1.zip` from evermeet.cx
    is pinned in the script (`FFMPEG_ZIP_EXPECTED_SHA256`,
    `FFPROBE_ZIP_EXPECTED_SHA256`), following the existing
    `HAVSFUNC_EXPECTED_SHA256` pattern and the `$ffmpegExpectedSha256` pin in
    `install.ps1`. evermeet.cx publishes no checksum file, so the hashes were
    computed from two independent downloads (identical) and cross-checked
    against the archive sizes reported by the evermeet.cx `/info` API.
  - Each archive is hashed with the existing `sha256_of` helper before
    extraction. On mismatch the archive is deleted, a `[WARN]` is printed, and
    `FF_OK` stays `0`, so nothing is copied into `.venv/bin/` and the installer
    falls through to its existing "FFmpeg not installed" handling.
  - `ZipFile.extractall()` is replaced by a guarded extractor that requires the
    archive to contain exactly the expected binary and rejects any entry whose
    resolved path would escape the temporary directory (zip-slip guard).
  - When `FF_VER` is bumped in a future release, both pins must be updated with
    it.
  - The Darwin download/verify/extract logic is factored into a self-contained
    `install_darwin_ffmpeg()` shell function so it can be executed under test.
  - `tests/unit/test_runtime_helpers.py` gains `test_install_sh_verifies_download_hashes`
    (asserts the exact trusted digests, the `sha256_of` check and the
    delete-on-mismatch statement, and that no unguarded `extractall` remains)
    plus behavioural tests that run the real shell function against fixture
    archives with a stubbed `curl`: matching archives install; a digest
    mismatch is deleted and rejected; archives with an extra, misnamed,
    `../`-relative or absolute member are rejected; a failed download installs
    nothing.

## CUDA 13.3 / 13.4

CUDA 13.4 is the current upstream toolkit (`cudart 13.4.49`, `nvrtc 13.4.59`,
`cublas 13.7.0.27`) but **cannot be adopted by this project yet**.

The prebuilt `torch 2.14.0+cu132` wheel is built and tested against CUDA 13.2.
No `cu133` or `cu134` Torch build exists on the checked PyTorch stable, test, or
nightly wheel indexes, so the CUDA component pins advance only within the 13.2
series (to Update 1). The inline comment in `pyproject.toml` records this
constraint so the finding is not re-derived on the next dependency sweep.

## Validation

- The Darwin FFmpeg branch was exercised in isolation with `curl` stubbed to a
  local mirror: genuine archives install both binaries (`FF_OK=1`); a tampered
  `ffprobe` archive is rejected with a SHA-256 mismatch warning (`FF_OK=0`,
  nothing installed); a crafted `../ffmpeg` zip-slip archive is rejected by the
  extractor guard.
- Full local pipeline (`./run_pipeline_localy.sh`) passes: Taplo, Bandit,
  pip-audit, Black, isort, Ruff, Flake8, Pylint (10.00/10), Radon, and Markdown
  lint.
- Test suite passes with the upgraded toolchain; coverage gate ≥ 90% per file and
  overall is maintained.
- `poetry check --lock` is clean against the regenerated `poetry.lock`.
